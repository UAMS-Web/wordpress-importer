# Continuous integration

The gate's jobs, what each one checks, and how the remote and local runs relate. [`AGENTS.md`](../AGENTS.md#running-things) carries the commands; this page carries the detail behind them. The runner's own flags are the [`local-ci`](../.claude/skills/local-ci/SKILL.md) skill's.

## The required remote checks

`main` requires three checks: `CI`, `Attribution footer` and `Closing keywords` (#163), the same three the Statamic add-ons require. `CI` is the last job in `.github/workflows/ci.yml`; it needs every other job and fails unless each one succeeded, so a skipped or cancelled job fails it. Add a new job to its `needs:` list in the same change; `scripts/ci-local.test.mjs` fails otherwise. **Each of those jobs runs on `ubuntu-latest` and `windows-latest`** (#186), as a matrix with `fail-fast: false`, and its check name carries the operating system. `CI` itself runs once, on Linux; a matrix job's result covers both legs, so a failure on either fails `CI`. The same test fails when a job loses a leg or gains `continue-on-error`. The other two are the jobs of `check-attribution-footer.yml` and `check-closing-keyword-across-lines.yml`. Every job but `CI` carries `if: vars.RUN_REMOTE_CI != 'false'`. The organization's variable is scoped to private repositories and does not reach this one, so only a repository variable switches those jobs off, and `CI` then fails rather than passing.

## The local runner

The runner is the shared one, [`.claude/skills/local-ci/local-ci.mjs`](../.claude/skills/local-ci/local-ci.mjs), configured by [`local-ci.json`](../local-ci.json) (wordpress-importer-archive#1319). [`scripts/ci-local.mjs`](../scripts/ci-local.mjs) only places its `--branch` slot, at `../wordpress-importer-local-ci`: the old `../wordpress-importer-ci` tree was made by the private runner this replaced, carries no runner marker, and the shared runner refuses to move it. Unlike `composer ci`, the runner does not abort at the first failure: one run surfaces everything the gate would flag. Read the summary block, not the exit code, and see the [`local-ci`](../.claude/skills/local-ci/SKILL.md) skill for `--comment`, `--commit-status` and the single-flight lock.

**The `dependencies` job is what keeps a reused slot honest.** In the runner's own slot it runs `composer install`, and runs `npm ci` when `node_modules/` differs from `package-lock.json`. Anywhere else it installs nothing and fails on drift, naming the command to run. See [`scripts/prepare-dependencies.mjs`](../scripts/prepare-dependencies.mjs).

## The jobs

**The gate is nine jobs that mirror `ci.yml`: `validate`, `pint`, `phpstan`, `rector`, `pest`, `changed-tests`, `spell`, `node-test`, `python-test`**, plus three local-only ones: `dependencies`, `synced-files` (a hand edit to a file the shared sync manages) and `handed-back-workflow` (`.github/workflows/clear-handed-back.yml` against its shared template). `changed-tests` (#306) runs a pull request's changed test files against the base branch's source and reports per file. It reports rather than judges: a test that fails there is often the point of the change, and the job fails only when the comparison could not run. It returns at once when no test file changed. Five of the nine are PHP, and `validate` runs `composer validate`: it catches a `composer.json` edit that left `composer.lock`'s content hash stale, which resolves fine and warns on every `composer install` until fixed. `pint` lints the whole tree plus every dot-directory holding tracked PHP, which Pint's Finder otherwise skips ([`scripts/run-pint.mjs`](../scripts/run-pint.mjs)). `spell` (wordpress-importer-archive#922, widened by wordpress-importer-archive#980) runs `cspell` over the prose corpus: `.claude/**/*.md`, `docs/**/*.md`, `README.md`, `AGENTS.md`, `CLAUDE.md`, `tests/CLAUDE.md` and `.github/**/*.md`, and refuses a run that checked zero files ([`scripts/run-spell.mjs`](../scripts/run-spell.mjs)). **`AGENTS.md` and the two `CLAUDE.md` files are in the corpus because they load into every session**, so they are the most-read prose here and were the least checked; `src/` stays out, per wordpress-importer-archive#922's reasoning that it spends the dictionary budget on WordPress field names for no prose coverage. `node-test` (wordpress-importer-archive#941) runs each `scripts/*.test.mjs` under Node's own runner, which needs no `node_modules` because those tests import only `node:` builtins and the shared runner. `python-test` (wordpress-importer-archive#1155) runs every `*.test.py` under `scripts/` and `.claude/skills/` through [`scripts/python-tests.mjs`](../scripts/python-tests.mjs), and fails, rather than skipping, when there is no Python 3 or nothing to run.

**Say what actually covered the diff, not that the gate was green.** The coverage is uneven and the shape matters: `spell` checks *spelling* in those paths and nothing else: not prose correctness, and not a Markdown file outside them. `node-test` exercises the scripts through their own tests. A `--branch` run hands off to the **branch's** copy of the shared runner when it differs from the invoking one, and prints `Handoff:` when it does, so a pull request that changes the runner is gated by the copy it ships. A change to `local-ci.json` alone needs no handoff, because the runner reads the job list from the branch's tree.

## The two mirrors

`.github/workflows/ci.yml` and `local-ci.json` are hand-maintained mirrors. `.githooks/pre-commit` blocks a commit that stages exactly one of them; for a genuinely one-sided edit, `git commit --no-verify`. [`scripts/ci-local.test.mjs`](../scripts/ci-local.test.mjs) checks the parts that can be compared mechanically: every `ci.yml` job is in `local-ci.json`, and the commands that can match do.
